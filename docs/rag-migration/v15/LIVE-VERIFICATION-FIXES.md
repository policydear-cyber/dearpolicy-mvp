# V1.5: fixes for the live verification after PR #49 (14 Oct 2026, release 5be9ec3)

**Source.** The household's live verification report: six turns in four conversations on the actual library, with trace findings.

**Access.** The live traces were **not read from this session**: production database access is not authorised here and was not attempted. Each finding the report traces is reproduced on the synthetic households that mirror the library's structure, and is fixed generally. The regressions are in `scripts/rag2-live-verify-regressions.ts` (`npm run rag2:live-verify-test`), on the real chat route with scripted model moves. They are plumbing and control evidence, not model results.

| # | Live finding | Cause (as reproduced) | Fix | Regression |
|---|---|---|---|---|
| 1 | Inventory omitted the unreadable upload | (a) `INVENTORY_QUESTION` (V1.4) did not recognise "list every document in our library…", so no inventory was produced at all. (b) A reply naming every readable document counted the unreadable upload as named, because its empty product name "matched". | (a) The classifier now covers library and every-document requests and still excludes paperwork ("documents I need to submit") and benefit questions. (b) An unreadable upload is named only by its file name. When it is missing from a reply that names everything else, its status line (file, reason, linked to whom) is appended from the library record. | INVENTORY ×3 |
| 2 | Limit fallback showed Group Living Care Plus S$300,000 for a death and a fracture question | `partialAnswer` showed the last three verified money values read in the turn, whatever they were about. `person_benefits` issues a value for every row on the certificate. | Only figures **about the question** are shown: label, product and printed conditions (and the same product's wording, e.g. Term Life's Death Benefit) must share a topic with the conversation. Most relevant first. With none, the turn restates what the conversation already established about the question (re-checked), or shows only the limit note. | FALLBACK ×2 |
| 3 | `person_benefits` returned 95 evidence records; follow-up turns ran out of budget | Every printed "Label: value" line of every linked document (a 36-page booklet) was returned. | The person's own rows and amendments are always returned. Shared wording is ranked by topic (an optional `topic` argument, else the conversation) and capped at 10, with the rest counted in `omitted`. A repeated `read_page` of the same page in a turn is answered by reference. | BUDGET |
| 4 | `calculate` with `percent_value_id` pointing at a printed amount was refused; no recovery, budget exhausted | Correct refusal, but no bounded recovery. | A wrong value type is still never used as a percentage. The one recovery is the percentage the document prints for the benefit row named (the same server read as omitting `percent_value_id`). It is noted on the result. With none, the refusal lists the percentages already read and what to pass instead. | FRACTURE ×2 (S$2,500 = 50% of the S$5,000 limit shown) |
| 5 | Contact step naming the insurer by its brand name rejected (certificate stored under the registered name) | Insurer check compared stored names only. | **Source-bound aliases:** the insurer recorded on another document of the **same policy number**, or an insurer name the document's own text prints. No similarity guessing. Unrelated insurers (the travel insurer, Lumen General) are still removed. | INSURER |
| 6 | S$2,000 rejected where the wording prints bare `$2,000` | Bare `$` names no currency. | A bare `$` amount takes a currency only from **its own document's declaration** ("all amounts are in Singapore Dollars", "Currency: SGD", "'$' means Singapore dollars"). A document that also prints another currency declares nothing, and no other document's S$ counts. If the real wording declares nothing, the sentence is still refused, correctly. | CURRENCY |
| 7 | Death first turn asked no question | Not traceable without the live wording. One plausible cause: a window worded "within 365 days from the date of the Accident" was not recognised. | The window pattern now accepts "from/of the date of (the) Accident" and "calendar days". | QUESTION |

**Not reproduced or not changed:**
- The sentence distinguishing unproven travel cover (rejected as asserting an exclusion), and the coverage-uncertainty sentence rejected for lacking evidence. Both need the live sentences and their citations, so they were not changed blind.
- The step naming the other (travel) insurer is not restored. It is still removed unless that insurer is the insurer of a personal document of the person that the answer relies on.

**Model input changed:** `person_benefits` has a new optional `topic` argument, and its results are smaller. The s50-live-2 replay still passes on this code, except that its tool schema now differs from the run's. A real-model run is needed to see the effect on token use and answers.
